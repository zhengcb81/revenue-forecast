# 收入模型逐项买方审计与改进记录

审计日期：2026-09-18。范围：原有全部 23 个注册模型，以及本轮新增的 8 个模型，共 31 个。审计对象为 `scripts/model_registry.py`、`scripts/model_extensions.py`、参数解析、相关公式测试及模型库文档。下列示例均为软件验证用合成数值，不是对任何公司的预测。

## 审计结论及准确性的含义

现有系统已经具备分部拆解、证据绑定、收入确认、存量连续性和确定性复算基础；但“数值可复算”不等于“预测准确”。本轮修复输入域、时点、非收入存量变化和数值精度漏洞，并补充八类经营机制。它能排除一组原先可能生成合理外观数字的错误，但尚未用真实公司历史样本证明预测误差下降，不能把测试通过写成“准确率提升 X%”。

最主要问题与处置：

| 发现 | 经济后果 | 本轮处置 | 剩余边界 |
|---|---|---|---|
| 所有 ratio 被当作 [0,1] 的概率 | 负利率银行、不同行业超过 100% 的相对生产率被错误排除 | 注册 `driver_bounds`，统一 `driver_value_bounds`；银行利率允许有符号，新店生产率允许大于 1 | 无上下限不表示任何值合理，研究层仍需证据、历史分布和压力范围 |
| `direct_growth` 排除 -100% | 无法表达关闭、停产、专利收入完全到期 | 下界改为 -1 | 零基数无法由增长率重启，必须采用实际经营驱动 |
| 客户数默认期初期末平均 | 年末大量新增会高估当年收入，早期集中流失会高估暴露量 | 加入新增贡献年比例和流失后损失年比例；默认 0.5 保留旧年中近似 | 聚合加权无法还原任意客户级曲线，需按 cohort 分部或预计算 |
| backlog 下降被统一解释为履约收入 | 外币折算或重分类减少会被计成收入 | 单列有符号 `backlog_remeasurements` | 新增订单、取消、合同变更与重估必须互斥且同口径 |
| 储量减少缺少非生产修订 | 经济可采储量下调可能被误认为销量 | 单列有符号 `reserve_revisions` | 储量分类变化不能替代品位、回收率、可销售库存与交付研究 |
| 直接调用注册入口绕过上层校验 | NaN/Inf、布尔值、缺列、错期、负存量可穿过纯公式 | 公共入口校验所有模型；补齐默认值；不修改传入数据；非有限或负收入失败 | 纯公式入口不代替证据、会计政策和完整发布验证 |
| 巨大存量相减吞掉较小新增量 | 合法的微小收入差额被浮点计算吞掉 | backlog、客户、交付、储量桥及银行加总采用 `math.fsum` | 浮点输入本身和乘法仍有精度极限；不能恢复源头已丢失的有效数字 |

收入确认应对应履约义务的履行及控制权转移；期间履约需要合适的进度计量，不能以订单或收款直接替代收入。这是共同会计边界，而不是某个乘法公式自动证明的事实。[IFRS 15 官方说明](https://www.ifrs.org/issued-standards/list-of-standards/ifrs-15-revenue-from-contracts-with-customers/)

## 统一检查方法

每个模型均按以下顺序审查：①经济恒等式和不可替代的原始驱动；②数量、价格、货币及时间单位；③期初—变动—期末桥和跨期连续性；④控制权、服务期及总额/净额；⑤参数域与极端情况；⑥生命周期适用性；⑦关键遗漏机制和切换条件。

下表公式中 `other` 是该模型明确列示且不重复的可加收入，不代表任意调平项。`T` 是有依据的时间比例，默认 1；比例按小数而非百分数字录入。年度化单价与期间平均暴露量只乘一次：已用全年平均客户、已交付数量或已年化实际产能时，不能再因同一件事乘半年度因子。每个跨期模型的首期 opening 还需与基期披露或有证据的基期推导锚点一致。

注册维度只检查“quantity”“revenue_per_unit”等类别，不能全面证明吨与千吨、美元与万元、MW×小时→MWh等单位代数。模型输入构建必须显式归一到公司币种和收入单位；跨币种汇率以及每千次展示中的 1,000 应各使用一次。来源缺失或无法校对单位时，停止发布数值。

## 原有 23 个模型逐项审查

| 模型 | 公式与量纲 | 审计发现、已改与保留限制 | 行业、生命周期与选用条件 |
|---|---|---|---|
| `direct_growth` | `R[t]=R[t-1]×(1+g[t])`，增长率无量纲 | 原公式正确但禁 -100% 不合理，现允许归零。不能解释销量/价格、不能从零基数产生收入；不应使用一条恒定 CAGR 掩盖周期或末期衰减 | 披露贫乏的成熟业务短期 fallback；收缩清退可用 -1；商业化前和拐点企业优先经营模型 |
| `direct_revenue` | `R[t]=已定义的收入[t]`，金额同币种同尺度 | 不伪造经营因果，适合会计收入定义难以安全拆分的情况；必须验证来源、年度与收入定义。直接入口现拒绝非有限值及负值；不提供增长驱动解释 | 所有阶段的有证据 fallback；复杂 IFRS 17、无法拆分的受监管收入；不应因字段少而获得较高信心 |
| `unit_sales` | `销量×单位净收入×T+other`，数量×金额/数量 | 需明确 units 是已销售/控制权转移数量还是年化潜在销量。returns、rebates、mix 已含在净单价时不得再次扣加。已交付全年实际量一般 T=1 | 工业品、汽车、消费电子及常规药品；上市后增长、成熟、替代衰退均可；重大库存变化改用库存桥 |
| `capacity_utilization` | `可用产能×利用率×良率×单位收入×T+other` | 利用率和良率 [0,1]；需区分投产产能、设计产能和销量。投入口径产能才另乘良率；合格品产能不能重复乘。产量≠销量，库存增长时需库存模型 | 半导体、制造、化工；投产爬坡与扩产；多工厂、多代际工艺应拆分，不以一个利用率外推 |
| `subscription` | `期间平均客户×年度收入/客户×T+usage` | 数学正确，重点在客户时间权重与 ARPU 含税/含usage边界。年度 ARPU 与月 ARPU不能混用；默认不表达新增、流失与提价的单独贡献 | 电信、会员、SaaS稳态；有客户桥时用 cohort，有 ARR 桥时用新增 ARR 模型；快速增长初期不宜期末客户代平均 |
| `usage_platform` | `合格活动量×每活动收入+fixed` | monetization_rate 是货币/活动，不能因名称含 rate 而当百分比。若活动量是 GMV，需与 take rate 单位和净额政策对应；补贴、退款、促销转化应有独立定义 | 支付、撮合、云用量、物流平台；扩张、成熟皆可；总额交易与净佣金收入必须有会计桥 |
| `services` | `可收费活动产能×利用率×单活动收费×T+other` | billable_capacity 应是可供工时/床日等活动量，不应直接输入员工人数再乘每小时费率。项目制固定总价不能机械按工时开票确认 | 咨询、外包、检测、医疗服务；扩张招聘、成熟与收缩；按技能/地区费率差异拆分，并核验可收费上限 |
| `project_backlog` | `期初+新签−取消+合同变更+非履约重估−期末`，所有项同金额口径 | 保留连续性；新增 `backlog_remeasurements`，区分外汇/合并口径变化和收入；使用 fsum。残差法只有在所有存量变化完整列出时成立，不能把未解释残差默认收入 | 工程、软件剩余履约义务、资本设备；在手项目稳定或跨期转化阶段。重大合同进度仍须单项目认定 |
| `resource` | `已售可销售量×实现价格+other` | formula 正确；不是储量×价格。明确品位、计价金属量、处理费/运输费/权益分成是否已反映；产销不一致需库存桥 | 矿业、油气、农产品、基础材料；经营期各阶段；价格周期和产量周期必须分开建模 |
| `reserve_depletion` | `消耗×回收率×实现价格+other`；`期末=期初+新增+修订−消耗` | 新增 signed `reserve_revisions`。消耗必须是同单位物理耗用，回收率只乘一次，经济储量重分类不产生销售。计算未自动连接库存、销量、品位 | 可追溯物理储量耗用的矿山/油气成熟与衰减期。药物研发管线不可凭此当确定性库存；土地若确认依赖交付应优先交付桥 |
| `infrastructure` | `收费量×适用费率+other`，活动×金额/活动 | billable_volume 应扣除免费/不收费量；监管涨价日期、阶梯价格、保底收费、补贴确认需另拆。名义流量不能替代可结算量 | 收费路、水务、管道、网络基础设施；投运后爬坡、稳态和特许权到期；到期续约不应默认自动发生 |
| `bank_revenue` | `平均生息资产×收益率−平均付息负债×成本率+手续费+other` | 修复负利率域并使用 fsum。只建模净利息及收入，不扣信用成本。需分资产/负债再定价、无息存款、套保和日均口径；负总收入仍不在通用模型支持范围 | 银行、特定信贷机构；信贷扩张、降息周期、存款流失。需要精细 ALM 时分资产桶/负债桶预计算，不以净息差重复乘利率 |
| `asset_management` | `平均收费AUM×费率+已确认业绩报酬+other` | AUM 应为实际收费资产；费率随产品组合、阶梯减免变化。市场上涨不是净流入；未结晶业绩报酬不能直接按行情计入 | 资管、基金、财富管理；稳态与周期波动；需要识别流入/流出/市场变动时用 AUM 桥 |
| `retail_franchise` | `平均直营店×店收入+加盟体系销售×已确认费率+供应收入` | 体系销售不是公司总额收入；加盟费与体系销售必须成对。供应收入限对外、扣内部抵消；加盟入门费是否分期必须依据合同。新店成熟过程未内生 | 餐饮、便利店、酒店加盟；直营转加盟、成熟扩张；直营爬坡优先新店 cohort模型 |
| `transport` | `运力×利用率×收益率+附加收入` | 此处 yield 是货币/有效运量，和制造良率含义不同。运力与收益率必须匹配客公里、吨公里、TEU航次等；不能用座位数乘每客公里单价 | 航空、航运、铁路；运力周期、客货结构变化；航线/航程显著变化需拆分 |
| `real_estate_rental` | `平均已占用面积×年度单位面积收入+other` | 已占用面积已经含入住率，不再另乘；合同现金租金与直线法租赁收入、免租期、租约激励不必相等；需单列会计桥 | 出租物业、REIT经营收入、数据中心面积租赁；招租爬坡、稳态及退租；销售型地产不能套租赁模型 |
| `licensing_commercial` | `治疗/商业化单位×净单价+里程碑+特许权费+服务收入` | 治疗人数、疗程、剂量和净价分母必须一致。管线失败概率不是已确认收入系数；里程碑条件及可变对价限制必须先验证 | 已上市医药、生命科学商业化、IP授权组合；产品导入与专利到期；商业化前使用有条件上市路径并分开事件结果 |
| `advertising` | `合格展示/1000×填充率×CPM+other` | CPM固定按每千次收费；若输入已填充展示，fill应为1。需区分可投广告时长、广告负载、广告主需求、无效流量和净收入，不能重复乘广告负载 | 互联网、媒体、流媒体广告；商业化初期至成熟；注意高广告负载对用户流失的反馈需在驱动场景中反映 |
| `gaming` | `期间活跃用户×付费转化率×期间每付费用户收入+other` | DAU/MAU与年用户收入不匹配会倍增；付费ARPPU已经含付费频次时不再乘频次。流水、渠道分成、虚拟商品递延服务期不同于收入 | 网络游戏、移动游戏；新品爬坡、运营成熟、生命周期衰退；多作品应按发行 cohort分拆 |
| `cohort_subscription` | `(期初客户+新增×新增贡献比例−流失×流失损失比例)×ARPU×T+usage` | 新增两项时点参数，默认.5保持传统平均近似；保留客户桥、连续性并拒绝负时间暴露。流失比例表示离开后未贡献的年比例。T不可重复计入同一时间效应 | 订阅、会员、电信、保险代理服务；高新增、高流失、收缩和转型；聚合客户ARPU异质性仍应拆分 |
| `delivery_pipeline` | `交付×单位收入×T+other`；`期末=期初+新增−取消−交付` | 库存订单桥和跨期连续性正确。交付不一定转移控制权；T只是明确的当期实现比例，已是全年实际交付时通常为1；价格变动需要 cohort | 航空器、船舶、设备、住宅交付；长周期扩张至订单收缩；公司取消口径和订单确认必须同边界 |
| `milestone_royalty` | `合格销售×版税率+已确认里程碑+服务收入` | 版税率 [0,1]；eligible_sales 是合同涵盖口径，不是被许可方所有收入。概率加权里程碑不当然符合收入确认；返还义务和最低保证费需另拆 | 医药授权、专利、内容IP、软件许可；开发期到商业化后；必须区分一次事件与可持续销量版税 |
| `insurance_service` | `服务/保障单位×已核对的每单位保险收入×T+other` | 只是已披露保险收入的受限分解，不是精算 IFRS 17 模型。coverage unit不自动等于保费或CSM，更不能把保费现金当收入；应核对准备金、服务释放及投资成分边界 | 能逐项对账的保险服务口径、各经营阶段；无法对账时应选择 direct_revenue，不宣称完整支持所有寿险/再保险 |

IFRS 17 下保险收入与保险服务费用和保险财务损益分别列示，保险收入排除投资成分；因此不能以 `coverage_units × 单位保费` 冒充完整的保险收入确认模型。[IFRS 17 官方说明](https://www.ifrs.org/issued-standards/list-of-standards/ifrs-17-insurance-contracts/)

## 新增 8 个模型逐项审查

新增模型均由注册工厂提供纯函数，无网络请求、文件写入或预测参数暗补。所有时间比例为显式必需输入；模型不会擅自假定所有企业在年中新增或退出。

| 模型 | 公式与桥 | 补足的机制、边界与限制 | 行业与生命周期 |
|---|---|---|---|
| `subscription_arr_bridge` | `流失ARR=期初ARR×(1−GRR)`；`期末=期初−流失+扩张+新增`；`收入=期初−流失×损失年比例+扩张×贡献年比例+新增×贡献年比例+usage` | 将 ARR 期末运行率和当年收入分开；拒绝没有留存客户却有存量扩张。GRR不含扩张，因此不能再放入含扩张的NRR。忽略同年新增又流失的复杂内部cohort，需预处理或拆分 | B2B SaaS、订阅软件；从商业化、快速新增、成熟提价到客户流失期 |
| `installed_base_aftermarket` | `期末装机=期初+新增−退役`；`收入=(期初+新增×时间−退役×损失时间)×服务附着率×每附着台年收入` | 硬件装机变为多年服务机会；退休不得超期初 cohort。不同设备年龄、维护周期、耗材用量与自有/第三方服务份额应拆分，不保证一台设备永续服务 | 工业设备、医疗器械、航空发动机、电梯、设备耗材；硬件增速放缓后的存量变现与退役衰减 |
| `store_cohorts` | `期末门店=期初+新增−关闭`；`收入=(期初−关闭×损失时间+新店×营业时间×新店生产率)×成熟店年收入` | 同店基盘、新开店、关闭及新店爬坡分开；新店生产率允许>1。上一年度新店在次年被视为期初店，长于一年的成熟曲线应拆出年龄组；不开“成熟即100%”的暗箱路径 | 餐饮、零售、诊所、健身；扩张、关店重组、恢复增长 |
| `renewable_generation` | `MWh=平均已投产MW×期间小时×限电前容量因子×(1−限电率)`；`收入=MWh×(合同占比×合同价+现货占比×现货价)+other` | 明确 MW 与 MWh；容量因子若已扣限电则限电率须设0。允许负合同/现货价格，净总收入仍不得负；小时数依实际财政期含闰年确定。平均投产容量已含投产时间，不再乘投产比例 | 风电、光伏等发电；投运爬坡、扩装、稳态和退役；储能价差、容量电价与辅助服务需另外分部 |
| `aum_fee_bridge` | `期末AUM=期初+流入−流出+市场变化`；`收费AUM=期初+流入×贡献时间−流出×损失时间+市场变化×时间`；`收入=收费AUM×费率+已确认业绩费` | 市场变化允许负值，不能与净流入混为一谈；拒绝负时间加权AUM。加权线性近似不等价于逐日净值与申赎路径；数据足够时应用披露日均/季度平均核对 | 公募、私募、财富平台；净流入扩张、熊市赎回、渠道迁移与成熟阶段 |
| `commercial_launch` | `有条件收入=min(合格年需求×采用率,全年供给能力)×商业化年比例×净单价` | 明确需求/供给较小者及上市时点。输出是给定获批与投产条件下的收入，未把成功概率隐藏为会计销售；eligible_units须为同一年度可服务需求，不是多年累计TAM | 新药、新材料、创新设备、新产品；商业化前至规模化初期。审批不确定性用明确延迟/失败情景，不把高情景当确定事实 |
| `finite_adoption` | `期末未采用市场=期初+新合格−退出−采用`；`收入=采用单位×净单价` | 用剩余可服务市场约束一次性采用，防止无限外推渗透率；期末非负与桥确保不超库存。市场不是静态全球TAM，必须限定地域、资格、预算与渠道；更换需求另建市场新增 | 耐用品、企业系统部署、设备安装、限定人群治疗；快速渗透、饱和与结构性衰退 |
| `inventory_sellthrough` | `期末库存=期初+合格生产+采购−报废−已售`；`收入=已售×净单价` | 区分生产和销售，防止把库存累积当收入；库存/销量一致且跨期连续。库存所有权边界必须固定，自有库存、寄售和渠道库存不可混桥；发货与终端零售另按合同判断 | 制造、品牌消费、半导体、医药、批发；补库、去库存、产能扩张、产品淘汰 |

## 生命周期切换与建模顺序

1. **未商业化**：先建可核验的事件日期、技术/监管/客户准入条件和供给约束，再用 `commercial_launch` 形成有条件路径。收入基数为零时不计算有意义的 CAGR；资金能否支撑到上市是收入实现前提，完整现金流交给财务模块。
2. **导入和爬坡**：优先显式时间权重、产能良率、渠道/新店成熟与订单交付；单一年度增长率不能同时替代所有机制。若关键时点跨度可能超过一年，场景改变时间，不只改变终值。
3. **快速扩张**：检验新增是否超可服务市场、供给和销售能力；区分现有客户留存/扩张与新增客户，新增门店与同店增长，生产与库存消化。
4. **成熟稳态**：用存量续费、更新、服务附着、价格/组合解释增长；检查提价后的需求弹性，防止同时假设份额、价格和利用率都持续上行。
5. **周期下行与重组**：允许负市场变化、负库存重估、关店、客户流失、收入归零；对恢复路径建立可证伪触发条件。供应约束解除不自动创造需求。
6. **结构性衰退和退出**：让剩余客户、储量、未服务市场和未履约合同真实耗减；专利/特许权到期、退役和产品停产进入明确年度路径。零收入后的重启用新的分部/新经营驱动。

公司往往同时拥有多个生命周期。模型按收入曲线和合同口径选择，不给整家公司贴唯一行业/阶段标签。更复杂模型只在新增数据能识别新增参数时采用；否则将不可识别机制列为范围和数据缺口，避免以自由度伪造精确。

## 核验记录与未覆盖事项

模型测试以反例和经济不变量为重点：31模型公式与原输入不变性、每个模型的 NaN/Inf 拒绝、客户加入与流失时点端点、-100%关闭、负利率、超存量消耗、外汇重估、储量下修、不连续年度、极端大存量下的小收入、8个新增模型的库存桥与边界。运行 `python -m unittest discover -s tests -p 'test_model*.py'` 核验模型层；全流程发布与行业案例由项目完整测试另核验。

保留的重要限制：

- 31模型仍是可审计的年度收入机制库，不是全部行业会计准则或完整企业财务模型。IFRS 17精算、银行日度ALM、复杂授权可变对价、季度季节性、客户级随机留存和多阶段药物成功率不声称自动覆盖。
- 存量桥及模型参数有依赖，单独扰动一个桥内参数通常会使恒等式失败；敏感性需联动派生闭合项或使用完整一致场景，不能关闭守恒校验。
- 同一周期、宏观因子、客户预算会同时影响多个驱动，低/中/高场景不是独立参数区间的笛卡尔积；数据相关结构和宏观传导应在研究阶段统一设定。
- 新公式说明、默认驱动trace和验证规则会影响输出哈希；旧冻结预测不得覆写，应保留版本及信息日期，在新版本重算并比较。
- 真实预测质量需要按公司类型、生命周期、预测距离做无未来信息的滚动回测，并与简单增长/不变收入基线比较。测试证明程序排除了指定错误，不证明经济假设正确。

注册接入采用 `build_extension_specs(ModelSpec, ModelRegistryError)`，再统一构造 `MODEL_REGISTRY` 及兼容视图；不在 `revenue_core.py` 添加模型分派。未来模型必须给出边界、存量/时点定义、会计适用范围、基础案例和至少一个经济反例，并进入全流程端到端测试。
