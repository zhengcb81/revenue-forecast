受验源码基线为实际 F4 检出的 `49a4013dbcdc12821d8b8de80df8d8c702633142`。本地 `main@d62fca9a3` 与它的共同祖先为 `f2215959`，本地另有在途计划及运行账本。候选以正式远端基线冻结，发布时独立核对两个分支。公开作业协议仍为 `rf-job/1`。

## 执行所有权

- 写入阶段的原反馈运行号、原尝试号、开始时间、请求摘要和代码字节版本之后，才落工作输入并发起子进程。启动被拒与已启动但无法确认结果分别记录。业务结果先落到所属作业，诊断投递随后进行。
- 新尝试写自己的结果、Markdown、源资料及发布登记。恢复选择已确认的结果；旧进程的迟到写入留在旧工作区。失去父进程时，来源可能已产生的效果和费用继续判为未知。F4 按原阶段编号读取历史，管理端对账可以补投原中断事实。
- 兼容历史作业的原固定布局。归档注册用同一套阶段布局解析已选尝试，仍校验完整字节、身份、来源和已发布结果。旧布局的迟到写入不能影响新布局。冷读既有记录只加载读证据及其公开端口。入册重放使用同一注册快照和证据校验，不穿透目录索引。历史 recorder 的观察、原始流和 seal 验证由公共的 owner 组件分别提供。
- FF 两流按字节捕获完成，以 UTF-8 单独解析业务文档，诊断提取只保留脱敏事实。无效编码仍保留原退出和单行机读回执。阶段本地日志落已知类型、原退出、行号或长度，去掉任意原输出和路径文本。正常产品工件继续按原模型接口完整保存。
- Windows 原子发布使用同一已准备的文件处理短暂的共享冲突。封存写在 Windows 使用目标已存在即失败的同目录原子移动，POSIX 使用保留相同语义的硬链接。

## 日周运行与诊断

日周 CLI 在公开 owner 查询前保存当前 RF 运行，原 manifest 继续代表最后一次已完成运行。中断后 `get-run --run-id <ID>` 原样查到开始但未证终态。重复查询不会触发 CWP 或 FF。周运行记录公开 FF 原编号、退出和脱敏异常位置。读请求按本仓明确的配置文件引用和原 receipt 访问。

在原 `--ledger` 参数下，`get-run` 返回最新运行，`get-run --run-id <RF run id>` 返回原运行。F4 的 `reconcile --owner-root <目录>` 可从 RF 现有 `assurance/runs` 读取日周记录。若本机运行采用自定义 ledger，按实际位置加 `--assurance-ledger daily <路径>` 或 `--assurance-ledger weekly <路径>`。没有终态的只读运行继续显示未确认。

## 验收

Windows 真实子进程、原有 CWP／FF 公开协议的本地替身、独占 owner 根。新增用例覆盖父进程强停后迟到写入、原尝试两次冷读、日志介质隔离、日周中断、错误字节与旧版档案。Linux 质量工作流纳入相同公开行为，新增独立 Windows 小集合。发布、全局技能副本和 Windows SYSTEM 排程的现场切换由总控验收。

独立复验用真 `submit` 产生合成作业，再三次用新进程查回。原身份返回成功和已知费用，分别改动运行号或尝试号后返回 `native_attempt_mismatch`，原账本字节保持一致。生产与回读共用原尝试的身份定义。完整 Windows 组发现三条旧 CI 和档案差异，修正后分别用真实二进制子进程、两种大小写路径、异根拒绝和迟到进程的定向组确认。
