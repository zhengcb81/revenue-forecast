# S2 RF 来源传输故障

基线为正式远端主线 `db4f8c7ab74aea7493caa29e6fd8040862095d7c`。候选在本仓隔离分支 `codex/s2-rf-transport`。本地主工区的分叉分支、未提交运行资料和计划保持原样。

## 根因与修复

RF 的 filing-fetch 客户端曾把上游非结构 stderr 同时写进诊断文本和机器错误流。真实上游进程返回非零但未给有效错误对象时，或退出 0 但返回坏 JSON 时，RF 客户端不能保持单条 JSON stderr。上层来源准备尝试解码整个 stderr，因此原始失败原因和上游进程退出值无法进入冷读。简单词模式也会留下多词认证值或无标记正文。

客户端沿已有错误 JSON 保留固定原因和已观测的上游退出值。非结构 stderr 只从 Python 依赖错误行提取已知类型名称作为提示，其余原文留在进程边界。来源准备和现有 F4 明细共享结构化原因，冷读该次来源失败不会重发。上游响应损坏没有证明请求用量，费用继续保留 unknown。结构化成功、拒绝、已知用量和公开状态收据沿用原路径。

## 复验

- 两条真实 CLI 离线反例均在基线失败。坏错误对象和坏成功对象分别使机器 stderr 变成 3 行和 16 行，合成探针也会进入原流。
- `tests/test_f4_failure_coverage.py` 的回归调用本仓客户端和来源准备两个公开入口，用同一个假 FF 程序分别触发原故障。检查 stderr 为单条 JSON，核对两次独立进程冷读一致、原因与退出值、F4 费用未知和模拟进程计数保持两次原始调用。检查输出与出箱文件不含合成值。
- 五组组合包括 F4 失败、S1 原回归、FF 客户端、来源准备及完整结果，90 项通过。组合使用独立临时状态，运行后已清理。五个 Python 文件的 Ruff 检查通过。验收过程没有访问真实上游或发生费用。
- ROOT 核对冻结文件的摘要并从独立进程复验两条真实入口，两项通过。最终作者复跑两项通过，专用临时验证根已清理。提交前直接查询远端 main，仍指向上述基线，可使用既有钩子做快进。源码发布和已安装宿主分别记录。本轮未部署宿主或技能副本。
