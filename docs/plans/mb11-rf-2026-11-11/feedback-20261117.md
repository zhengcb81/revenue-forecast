## 共同接口

本仓从真实运行、单模块 E2E 或业务独审取得有效运行/attempt、原步骤、期望与实际，投影为独立的 UTF-8 JSONL。每行一条 `feedback-observation/1`。下例是离线偏差样本，接收后仍需归责。

```json
{"schema_version":"feedback-observation/1","owner":"revenue-forecast","origin_owner":"revenue-forecast","run_id":"fixture-run","attempt_id":"attempt-1","step_id":"consume-summary","check_id":"pinned-narrative-adoption","expected":"requested-version-applied","actual":"prior-version-applied","evidence_ref":"fixture-event-1","version":"fixture-v1","disposition":"deviation"}
```

必填字符串是 `schema_version, owner, run_id, attempt_id, step_id, check_id, expected, actual`，预期和实际使用稳定结果词。owner 指能修复问题的模块，origin_owner 是最初发现问题及最终回告的接收模块。可选字段为 `issue_key, evidence_ref, version, parent_step_id, details_ref, disposition, origin_owner`。disposition 可为 expected、deviation 或 unknown。原生作业、来源、日志及审查定位作为不透明引用，owner 在本仓解析。已确定的通用问题才给稳定 issue_key。相同错误文字或公司名不足以归并根因。一个运行的多条观测可关联同一问题。

业务协议与既有 stdout、stderr 维持原格式。事件按公开操作记录开始、结果、选择的路径、原因、实际版本及父步骤；原生日志已覆盖的部分通过引用读取。单独的反馈输出写入失败记追踪不完整，业务终态、计量和付费恢复仍由原责任层判定。单测/E2E 使用独占的短临时目录。密钥、认证头、整份原件、完整模型响应及生产库均不进入交接记录。成功明细轮转，开放问题仅固定最小脱敏复现材料；记录每轮新增磁盘量。

## 实施和公开重放

1. 在过程侧关联 RF 原生 job、run、attempt、输入 artifact 及实际执行版本。对照请求 NarrativeRef、实际准备的输入、模型使用的 evidence/claim 以及最后报告版本。把“资料存在”“成功读取”“参与预测”分别作为观测。已有 W20 工具先读端口结果，缺少真实采用证据的路径记 unknown。
2. 由选定参数及支持诊断生成业务质量观测。汇总成功时仍可报告币种/量级错位、估算幅度无经营依据或不同业务角色混用。审核形成 issue 时保留原报告定位；定性观点和敏感度大小由分析师结合证据判断。配置正确且缺足够证据的预测应明确不确定性。
3. 构造相同公司和口径、两个有效摘要版本的离线输入。制造“声明新版本、消费旧绑定”的 RED，再验证真正采用、仅浏览、没有适用材料的合法情况。第二个文种或不同公司替换输入后同一检查仍有效。处理真实缺陷时在模型/准备或采用观察的第一次偏离处修改。
4. 总控 P1 给出真实新版及已恢复版本的公开引用后，在隔离 RF 运行根经公开入口消费。记录采用了哪个 claim/来源定位、参数或公开产物、实际版本、原/恢复输入的结果；若资料仅供背景，保留如实的理由。跨回合旧产物只能证明旧版本。

## 本仓 issue 与修复技能

建设 `repair-rf-issue`，接收本仓已确认的 issue 或选择当前最影响主线的一项。利用已有问题卡/审查映射；无现成权威处置记录时，在本仓用一张小卡保留状态、各次 occurrence、影响、原生定位、根因、PWF 工项、回归用例、修复版本及发现方复验。先复现首个公开偏差，再在真正责任层修复、跑原错例和相似合法例。跨模块缺陷交给相应 owner；受理、处置和回告只交换受版本约束的公开结果。未查清、外部限制或未知费用分开记录。修复版本先记已修，原消费场景重放通过再结案；再次出现可关联历史并重开。

## 两个验收节点

1. 离线验证和恢复。`python -B -m pytest -q tests/test_w20_narrative_adoption_audit.py tests/test_w20_narrative_adoption_e2e.py tests/test_research_support_diagnostics.py`。涉及作业发布时再定向追加 `tests/test_rf_job_facade_cli.py`。真实验收只复跑受影响消费者；旧周跑记录、正式输出、付费余额和历史报告保持原用途。
2. 用实际公开入口重放原偏差，将结果回告发现方；关键内容和跨边界节点请未参与实现的 agent 独审，识别的问题修复后再交付。普通改动跑受影响快测即可。带上 RF job/attempt、报告版本、输入定位、被采用的 claim 或没有采用的原因，以及 CWP 公开来源版本。独审抽查一条实际消费链和一个算式成功但依据不足的反例。

交接写明 owner、实际 base/commit、执行版本、证据引用、期望与实参、运行命令/退出码、哪些只做过离线、临时根清理、独审结论和可继续的未决条件。总控只消费公开输出。总调度入口是 company-wiki 的 `docs/plans/feedback-loop-2026-11-17/task_plan.md`。
