# revenue-forecast 买方方法审查与改进报告

日期：2026-09-18。工作区版本：4.1.0；标准预测输入/输出仍使用 schema 3.7，矿业扩展 3.8 保持可选。

## 一、审查结论

原系统的优势是来源追溯、收入确认、情景复算和发布约束。主要不足是部分研究规则会引入锚定，若干公式缺少时点与非收入存量变动，误差评估缺少可比基准和使用日期约束，行业说明把形式相似的业务误认为具有相同经济机制。

本轮已修改可执行代码、技能入口、模型库、研究步骤和测试，而非只提出建议。原有 23 个模型全部逐项审查，新增 8 个，合计 31 个注册模型；方法路由覆盖 20 类行业、7 类生命周期和 6 类特殊公司情形。

这里的“准确性提升”有明确边界：已验证的是公式正确性、时点处理、信息集纪律及错误输入拦截能力。尚未完成真实公司跨行业的滚动样本外 A/B 实验，因此不能宣称平均预测误差已下降某个比例。

## 二、重要发现与已落实改进

| 优先级 | 原问题及投资研究影响 | 已落实的修复 | 验证方式 |
|---|---|---|---|
| 高 | 管理层可比目标必须进入某情景，可能把愿景变成 High 的硬下限 | 新增有证据的 `independent_benchmark`，三情景完整披露兑现度，但允许全部不达标；独立比较单独计数 | 不达目标仍可发布；缺反证理由/证据/映射则失败 |
| 高 | 年末运行率直接与全年确认收入相比，造成 ARR/收入混同 | 要求显式转换公式及注册参数；逐项重算转换金额；缺桥时保留数据缺口 | 缺转换、转换金额错误、错误映射被拒绝 |
| 高 | 历史准确性摘要未绑定公司、币种、口径及可用日期 | accuracy 1.1 绑定身份、财政年末、预测日及实际数据可用日，防止使用未来结果和重复快照/预测起点 | 前视泄漏、跨公司、币种尺度错误、重复计分测试 |
| 高 | 对多个 WAPE 按样本数平均不等于合并误差率；零收入样本可能被忽略 | 使用 `sum(abs(error))/sum(abs(actual))`；零实际样本的误差仍进分子 | 不同收入规模、零收入样本手算比较 |
| 高 | 专利到期、设备退役被描述为储量耗用并产生收入 | 限定 `reserve_depletion` 的物理耗用边界，重写药品、地产、制造与矿业路由 | 全 31 模型逐项经济审查；明确仍需人工核对的单位语义 |
| 中 | 新增/流失客户默认年中发生，无法表达年末签约 | 加入新增贡献期与流失损失期；另增 ARR 存量与确认桥 | 年末新增 ARR 不产生当年订阅收入；流失、扩张单列 |
| 中 | backlog、储量的外汇/重分类/修订可能被误算成收入 | 新增 `backlog_remeasurements`、`reserve_revisions`，保持与收入变动分离 | 非收入存量调整反例、跨期连续性与金额复算 |
| 中 | 所有比例均限 0–1，增长不允许 -100%，限制负利率和停业业务 | 注册统一边界，计算与敏感性共同使用；支持负利率、归零、超过 1 的相对生产率 | 边界、共享参数范围交集、负数冲击方向测试 |
| 中 | 纯计算入口可绕过参数校验，浮点大数相减损失小额变化 | 校验数值有限性、类型、路径长度和驱动完整性；关键加总使用 `math.fsum` | 所有注册模型 NaN/Inf/布尔值等反例、极端金额测试 |
| 中 | 缺少朴素预测基准，复杂模型即使不优于简单外推也无法识别 | 增加偏差金额、RMSE、MASE/RMSSE、平基期及历史 CAGR 基准和相对技能指标 | 冻结训练历史手算、恒定/零历史边界测试 |
| 中 | 分数和 Low/High 易被解读为成功概率或置信区间 | 明确为证据/流程评分与情景范围；少于 5 个观察或 3 个起点折减历史得分；披露区间宽度 | 回测与评分重算；文档和输出共同说明 |
| 中 | 模板默认 direct_revenue 却生成 ratio 参数，且历史顺序与日期不合理 | 根据注册模型生成字段与量纲，加入首期存量锚点，支持逐分部 `--segment-model` | 31 模型模板路径、维度和首期锚点逐项验证 |

关键代码：[模型注册与校验](../scripts/model_registry.py)、[扩展模型](../scripts/model_extensions.py)、[目标处理](../scripts/research/targets.py)、[回测](../scripts/revenue_backtest.py)、[准确性记录契约](../scripts/contracts/document.py)、[敏感性](../scripts/analysis/sensitivity.py)。

## 三、逐步骤的方法升级

| 研究步骤 | 改进后的判断要求 |
|---|---|
| 冻结信息集 | 明确公司、时间、会计口径和版本；不把后来发布的回测结果带回先前信息集 |
| 行业/公司/阶段识别 | 先按分部判断收入机制，再选择生命周期路由；同一公司允许新旧业务处于不同阶段 |
| 历史与基期 | 对总额/净额、并购、外汇、重分类和非经常事项建立可比桥；首期存量需来源锚点 |
| 九维研究覆盖 | 研究结论必须落到驱动、收入确认、反证或数据缺口，不能直接加到 CAGR 或置信分数 |
| 管理层沟通 | 保存原文、时点、目标强度和期间口径；可独立否定目标，不因管理层乐观而抬高情景 |
| 定性到定量 | 写出机制、观察指标、参数方向、幅度依据、时滞、反证和更新触发条件；同源转述不当多份独立证据 |
| 模型选择 | 按经济恒等式、可观测驱动与数据质量选择；未知多时允许透明 fallback，不以模型复杂度替代可信度 |
| 情景建设 | 使用一致的需求、价格、供给、客户留存与时点组合；上市失败、延迟、停业和复苏允许不同路径 |
| 收入确认 | 区分订单、存量、产量、销量、ARR 与收入；服务暴露期、交付与进度不可重复折算 |
| 聚合与归因 | 先约束分部再汇总；现有“权重×分部净增量”只属分配，不能称经过识别的因果贡献；负/正业务分别保留 |
| 敏感性与反证 | 选择可行的冲击单位和幅度；存量桥中的关联输入应一致调整，不把破坏恒等式的机械单变量冲击当有效压力情景 |
| 校准与交付 | 模型结果与平基期、历史增长基准同时评价；完整保留失败模型和短历史限制；正式数值只由验证后的结果生成 |
| 冻结与跟踪 | 在结果未知时冻结；按期限、行业、生命周期拆分真实误差，再决定模型是否值得保留 |

完整执行方法见 [买方研究方法](../references/buy-side-methodology.md) 与 [技能入口](../SKILL.md)。会计确认边界依据 [IFRS 15 官方说明](https://www.ifrs.org/issued-standards/list-of-standards/ifrs-15-revenue-from-contracts-with-customers/)，银行和保险仍需各自适用的报告口径。

## 四、新增模型与覆盖范围

| 模型 | 主要新增能力 | 适用情形 |
|---|---|---|
| `subscription_arr_bridge` | 期初 ARR、总留存、扩张、新增和期末 ARR 闭合；按发生时点转为收入 | SaaS 扩张、成熟、降级/流失、增长转收缩 |
| `installed_base_aftermarket` | 装机、新增、退役和附着服务率 | 工业设备耗材、医疗设备售后、服务化转型 |
| `store_cohorts` | 旧店、闭店、新店、营业期和新店生产率 | 连锁扩张、整顿、闭店转型；多成熟期需分 cohort |
| `renewable_generation` | 投产 MW、小时、限电前容量因子、限电、合同/现货电价 | 风光电投产爬坡、成熟、负电价情景 |
| `aum_fee_bridge` | 期初 AUM、流入、流出、市场变化、收费暴露期 | 资管规模增长、赎回、市场下跌和收费结构变化 |
| `commercial_launch` | 需求采用、供给上限、上市时间、净单价 | 预收入、获批后商业化、新品推出；为条件收入，不内嵌成功概率 |
| `finite_adoption` | 有限未覆盖市场的进入、退出和首次采用 | 渗透、饱和、有限改造池；重复购买另建分部 |
| `inventory_sellthrough` | 库存、产出、外购、报废、销售与期末余额 | 制造、分销、去库存与产销错位 |

详细字段和局限见 [新增模型说明](../references/extended-models.md)。原有每个模型的公式、风险和生命周期适用性均在 [31 模型逐项审计](buy_side_model_audit_2026-09-18.md) 中列示。行业与阶段组合见 [行业及生命周期路由](../references/industry-lifecycle-routing.md)。

## 六、仍需分析师判断及后续精度验收

1. **真实样本外准确度**：应对真实公司按冻结起点、同一信息集、相同预测期限比较旧/新方法与简单基准，至少分别检验增长、成熟、周期下行、预收入及转型样本。保留公司退出、失败上市和预测失败，避免幸存者偏差。
2. **会计与单位语义**：公式字段的 dimension 不能独立证明矿石吨/金属吨、产量/销量、GMV/收入或保费/保险服务收入等语义相同；完整 IFRS 17、复杂银行报表、联合药物成功事件不在通用收入引擎中自动完成。
3. **概率与因果识别**：本轮没有自动估计相关情景概率、统计预测区间、Shapley 归因或客户级 cohort 参数；启发式置信分数、手动权重不能替代这些估计。
4. **记录真实性**：准确性摘要的格式、日期、统计量与哈希校验提升一致性，不能认证填写者确实拥有对应原始文件；需审计归档 snapshot/evaluation 及其来源，不可将重算哈希视为来源认证。
5. **版本兼容**：旧快照与发表结果保留原文件并使用原版固定运行时复验。4.1.0 的新校验不得通过改写旧版本号/重新散列旧快照来冒充历史保证；新的输入和假设生成新的预测版本。本轮修改在该项目工作区，未执行外部安装同步或发布。

## 七、使用新增模型

例如生成 SaaS 分部的输入骨架：

```powershell
python scripts/generate_input_template.py --name "Example SaaS" --base-year 2025 --forecast-years 2026 2027 --currency USD --unit million --segments Core --segment-model Core=subscription_arr_bridge --output input-template.json
```

骨架保留 FIXME 与占位哈希，不能直接作为预测发布。填入经过核查的来源、参数、时点和会计政策后，继续沿原有 lint → hashes → validate → forecast 流程执行；准确性记录详见 [回测说明](../references/backtesting.md)。
