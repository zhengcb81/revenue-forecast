现有方法能帮助识别会严重影响收入预测的经营和会计边界，但本轮没有形成投资委员会可直接采用的收入预测。小米草算可以解释不同条件的收入量级；微软形成了及时修订口径的假设框架；紫金完成基年关键口径核验。它们距离可采用预测的差距同时存在于来源流程和经济证据，修通来源后仍需完成研究。

## 小米：有用的当年桥，关键增长源仍未获得经营验证

**确认有效的研究步骤。** 独立打开年报验证FY25总收入及五条外部收入曲线；IR中报链接在本审计端403后，从HKEX公告目录点击实际公告，重新核对H1 2025/2026五曲线和总额。草算按“已实现H1+剩余H2”锁住实际，避免用全年增长率覆盖已发生结果；保持EV/AI整体精确基数，未把舍入的汽车/其他收入伪装成精确拆分；全部九个年度情景总额独立重算相符（仅机器浮点舍入差）。[2025年报](https://www1.hkexnews.hk/listedco/listconews/sehk/2026/0428/2026042800526.pdf)，[2026H1公告](https://www1.hkexnews.hk/listedco/listconews/sehk/2026/0818/2026081801014.pdf)。

**IND-X01 / P1 / 研究缺口：EV驱动大部分增量，却未做产能、订单和车型组合的量化约束。** 审计重算Base2028公司比2025增量105,421.6百万元，其中EV/AI贡献75,430.5百万元，占71.55%。Base2026H2需要月均49,157.5台，较Q2月均交付提高41.5%；High要求60,824.2台，提高75.1%。这些路径并非算错，但草案没有工厂有效产能、车型上市时点、净订单/取消、交付爬坡和相互蚕食的桥。Base2028汽车交付下调10%、净ASP固定时，仅汽车收入就少17,250百万元，约占该情景公司收入3.1%；这是本审计的局部量级检查，不是正式敏感性结果。应把补证重点首先放在这条曲线，优先于细化小业务。

**IND-X02 / P2 / 研究缺口：成熟手机业务量价同时改善的解释未独立校准。** Base H2采用71百万台×1,350元；High为79百万台×1,390元。价格和量可同时改善，但需地区/档位组合、替换需求、渠道库存及竞争价格约束。目前“高端化、海外扩张”没有给出能推导量级的桥。先与可比市场总量及隐含份额对照，再判断是否支持该范围，不能仅因变量命名为unit_sales就视为预测更准确。

**IND-X03 / P2 / 研究缺口：IoT复苏和EV其他收入成为未充分解释的剩余项。** Base IoT从当年H2零增长转到以后8%/7%，缺补贴退坡、品类基数和海外分销兑现桥；EV/AI other从2026H2的2,500到2027全年6,500、2028全年9,000百万元，缺可比年度拆分和装机服务/附件/AI收入机制。列为assumption是正确纪律，仍不足以证明数值可采用。

**IND-X04 / P2 / 会计与覆盖缺口：互联网混合收入不能被单一确认标签掩盖。** 年报原文确认展示广告、效果广告、游戏及金融业务有不同确认方式，总额/净额也需区分。当前草算尚未假填单一政策，这是正确停点；正式化前须有材料支持拆分，或在已确认收入层建透明桥并明确重大性限制。官方电话会Q&A尚未实际读取，EV交付目标仍待原话验证，因此管理目标覆盖不能宣称完成。[年报会计政策，印刷页297–299](https://www1.hkexnews.hk/listedco/listconews/sehk/2026/0428/2026042800526.pdf)。

## 微软：重分类处理及时，但八条曲线并不等于八套经营预测

**确认有效的研究步骤。** 独立打开9月2日SEC Exhibit，FY2025/FY2026八条重述收入之和分别与公司总額281,724/331,839百万元一致；新两分部与八线映射吻合。旧Azure、GitHub、LinkedIn等边界已改变，生产者撤回旧三分部模板有必要，避免双算与错误同比。对CC、GAAP、ex-TAC、季度和全年指引的区别有明确记录。[SEC重分类与指引，slides15–21](https://www.sec.gov/Archives/edgar/data/789019/000119312526380280/d291965dex991.htm)。

**IND-M01 / P1 / 研究缺口：收入因果仍几乎全部压缩成增长率判断。** 八线×三年×三情景共72个增长率，模型都选direct_growth。透明回退优于编造单位数据，但不能因此称经营驱动预测已完成。审计按草案独立复算BaseFY2029为529,267.4百万美元，三年CAGR16.84%；Azure贡献公司增量67.64%，Azure+M365 cloud占终期收入73.81%。最重要判断集中于Azure，却没有计费消耗、容量兑现、净价格/折扣、主要客户集中度和可服务需求的量化上界。

**IND-M02 / P2 / 研究缺口：季度指引尚未与全年形状闭合。** Azure FY27 Q1 CC44–45%被用来支持全年40%的Base，但没有Q1美元收入与Q2–Q4需要实现的季度/半年路径，也没有同比基数、FX与在期确认的单列桥。Windows/Xbox相反，需要展示当期下降后全年复苏所要求的后续季度改善。不能将季度指引乘4，也不能只写“下半年放缓/恢复”就认为年度校准完成。

**IND-M03 / P2 / 研究缺口：中长期衰减斜率缺参考类或误差校准。** Base Azure40%/32%/25%、M36517%/16%/14%是明确标识的分析师假设，但两个新口径年度历史点与一个同业低增速样本不足以校准3年路径。把Azure每年的Base增速都降低5个百分点，独立局部复算FY2029公司收入减少25,749.5百万美元，约4.9%。如此重大的自由参数需要客户/容量/价格证据和范围敏感性，不能被“72个有rationale的参数”替代。

**IND-M04 / P2 / 研究缺口：新旧迁移与AI采用的净增量尚未闭合。** M365云增长与许可下降分别设率，没有同客迁移、席位/用量、折扣、现有产品替代及服务捆绑桥；产业应用云KPI和整个混合业务、广告ex-TAC与GAAP收入也未量化转换。草案正确披露差异，正式预测仍需解决或缩小解释范围。

## 紫金：基年口径审查发现高影响风险，不能跳到未来表

独立检查已核hash原件的PDF第45与326页渲染：2025对外收入349,079.1百万元，内部销售234,970.1百万元；含内部销售的分部总额若直接相加，会比对外收入高67.31%。这是假设错误做法的影响量级，不是本次已生成预测出现67.31%错误。产品表单位万元、附注单位元必须先统一；产销表明确排除非控股企业，摘要/项目权益量不能直接当并表销量。

**IND-Z01 / P1 / 研究缺口：未来销量×价格尚不能勾稽分部外部收入。** 矿产、冶炼和贸易需分别处理含量/净结算价、内部销售、库存与交付/结算时点；对已并表矿山再乘权益比例会少算，将联营产量乘价直接入并表会多算。底稿正确识别风险，但尚未形成可重构历史的经营桥。

**IND-Z02 / P1 / 研究缺口：截止日最新实际与价格/项目证据不足。** H12026无法通过当前链路取得；最新金属价格/期货曲线、并购范围变化、项目投产/爬坡、数量目标转收入、黄金与铜不同风险路径未完成。无三情景输出属于诚实的未完成状态，不能用年报产量目标与即期价格替代。

基期检查可降低显著口径错误；它不证明资源模型、reserve_depletion或新生命周期模型在真实紫金数据上已运行正确。原件路径和图像见ZIJIN目录，未来数值未产生，因此不对预测精度作通过评价。

## 共同判断与后续修复验收建议

1. **先修通资料到可用来源的契约。** 保留当前失败证据和raw；处理IND-D06注册断点及IND-D01 review入口后，用相同三家公司重新跑reuse→缺失→授权获取→再次reuse，分别保存调用预算、hash、索引和worker状态。
2. **先补能改变收入结论的证据。** 小米汽车与手机、微软Azure/M365、紫金并表外售量与价格应优先；不要为覆盖31个模型而增加无法观察的自由参数。
3. **将年内已实现数据和短期指引桥入年度。** 小米H1锁定有实际价值，应在正式输入和输出中可重算；微软Q1指引、紫金H1实际也需要相同纪律。
4. **补经济验证后再做发布验收。** 完整输入/claims、三情景、关键敏感性、management目标/反证、正式CLI验证、来源与发布registry、不可变snapshot缺一不能宣称完整运行。无正式工件，本轮无法独立重放输出验证或检查snapshot。
5. **预测准确性仍为未证实。** 本轮没有匹配信息集的冻结滚动预测与后续actual，也没有基准误差比较。算术重算、hash正确、场景顺序或丰富叙事，都不能证明未来误差降低。建议之后采用真实冻结起点、同口径简单基准和按驱动复盘，保留失败样本。

研究层面的P1/P2说明“若用于正式买方预测会有何重要不足”，不是宣称底稿故意误导或所有问题都是引擎缺陷。本次生产者持续标明草案身份，未将非正式数字冒充正式预测，这一点通过。
