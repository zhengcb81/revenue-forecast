# 买方收入预测方法：从可检验假设到可复核路径

本文件定义研究标准和人工审查步骤。它不扩大 revenue-forecast 的收入边界，不替代既有来源、参数、会计、签名和发布契约，也不意味着这些研究步骤已成为代码门槛。已执行的约束以验证器和测试为准；研究备忘中的新字段不能直接写入正式 JSON。

## 1. 先冻结问题，再建立独立基准

在用管理层远期目标确定参数前，记录研究对象、信息日、收入口径、预测年限及最重要的三个不确定性，并保存独立基准的推导。区分“未来可能发生什么”“需要满足什么才能达到目标”和“当前证据支持什么”。按业务分部选择生命周期，不能用上市时间、公司规模或公司整体增长率代替业务阶段。

建立两条互相检验的路径：

- **内部路径**：客户或资产存量 → 活动量 → 供给与交付 → 净实现价格 → 会计确认。
- **外部基准**：同口径市场需求、可比企业渗透/留存/爬坡、历史周期、替代品价格与渠道库存。先列入组条件，再选样本；保留失败、退市、延期和未商业化样本，解释幸存者偏差。

两条路径不一致时，研究差异，不取简单平均。市场总量只能约束可服务需求；市场份额需要渠道、产品、价格、产能或客户证据。管理层目标作为随后核对的基准，不自动成为 Base 或 High。管理目标的可执行记录方式见 [management-targets.md](management-targets.md)。

## 2. 建立收入口径与历史桥

按报告口径对齐币种、财年、并表范围、总额/净额、持续经营、一次性收入和分部重分类。保留原始历史和可比历史的桥，不覆盖原始值。至少两期历史是运行时最低要求，不能视为足够估计周期、季节性或长期趋势；通常争取三至五年、可得时八至十二个季度，周期企业争取覆盖完整周期。数据不足则减少自由参数和缩短明确预测期。

检查销量与出货、终端动销与渠道进货、付费用户与活跃用户、合同金额与履约、ARR 与年度收入、系统销售额与加盟费。季度合计年度时核对财年、额外周、汇率和分部重述。收购、处置、汇率、价格、数量、组合和确认时点分别解释，只能在一个桥接位置入账。

收入确认以适用准则及公司政策为依据，不能仅凭业务模型名称决定。IFRS 15 的合同与履约义务框架要求把经营活动映射到控制权转移或履约进度；它支持此处的确认桥，并不证明分析师的需求假设。[IFRS Foundation：IFRS 15](https://www.ifrs.org/issued-standards/list-of-standards/ifrs-15-revenue-from-contracts-with-customers/)

## 3. 把定性判断落到参数和反证

每个重大假设写一张研究卡。卡片是研究备忘模板；正式值仍进入已有参数、claim、growth_driver_tree、research_coverage 和 data_gaps 字段。

| 研究卡项目 | 应回答的问题 |
|---|---|
| 命题与替代解释 | 哪个事实支持什么变化？相同事实还能由库存、季节、促销或会计变更解释吗？ |
| 传导机制 | 谁改变采购/使用行为，通过什么合同或渠道，在多久以后影响哪个参数？ |
| 基准与量级 | 历史、同类样本或可验证单位经济关系支持多大变化？为何本企业不同？ |
| 适用范围 | 哪个产品、客户、地区、年度和情景？是否已经包含在价格或留存率里？ |
| 证据与依赖 | 原始来源是谁？多条新闻是否复述同一订单或管理层发言？ |
| 反证与触发 | 出现什么可观察阈值将改变数值、延迟时间或撤销假设？何时检查？ |
| 未解不确定性 | 哪一条证据缺口会改变结果，缺口可能影响多大收入？ |

不要把“技术领先”“品牌强”“政策支持”“优秀管理层”直接转为增长率加点。以下转换是研究要求，数值仍需独立证据：

| 定性观察 | 可验证机制与参数 | 常见反证 |
|---|---|---|
| 更换系统成本高 | 同一客户群的毛留存率、到期续约、净缩减；区分锁定与真实使用 | 留存高但席位和用量下降，价格补贴维系 |
| 产品性能提升 | 客户验证 → 中标/转化率 → 可交付量；校正价格与产品组合 | 评测好但验证延期，渠道缺失，替代品降价 |
| 提价能力 | 同口径净价、折扣、退货、留存与销量弹性的组合 | 标价提高但返利加大、量下降或应收拉长 |
| 新产能扩张 | 投产时间、良率、利用率、瓶颈及订单覆盖 | 设备已装但认证、员工、能源或需求不足 |
| 政策催化 | 适用客户、预算拨付、审批、招标和履约时点 | 政策未执行、补贴递减、客户提前采购 |
| 第二增长曲线 | 新旧产品分开，迁移客户、蚕食率、停产与渠道迁移 | 新业务增量来自原业务转移，旧业务流失更快 |

来源独立性和因果方向必须人工判断：多个不同 URL 不保证独立；历史相关性不证明新增供给创造需求。证据评分用于定位薄弱处，不能替代反证搜索。

## 4. 最小充分模型与逐层交叉验证

先选能重构历史的最少参数模型，再因明确误差来源增加结构。逐层检查：

1. **维度**：存量、期内流量和价格分母一致；年度、月度、人次、人数、吨矿石和吨金属不能互换。
2. **存量流量**：客户、订单、AUM、储量、产能的开期、流入、流出、关期衔接；流出是否真的产生收入。
3. **期间权重**：新客、开店、投产、交付在年内何时发生；期初期末平均只在均匀变动时近似成立。
4. **商业约束**：需求、供应、渠道和履约能力的最小值，及跨分部共用瓶颈；受限收入不能凭空转移到其他业务。
5. **会计桥**：交易额、数量、账单、合同负债和履约之间的转换；避免经营模型已确认收入后再乘一次进度。
6. **独立复核**：用历史单位收入、销量隐含市场份额、可用容量和外部基准检查隐含假设。

每个模型的适用和失效条件见 [model-library.md](model-library.md)。更多公式并不自动提高准确率。现有显式模型评分是一项结构性指标，不是样本外优势的证明。

## 5. 让情景表达机制，而不是上下浮动百分比

每个情景给出一套内部一致的需求、价格、供给、竞争与确认假设。低情景不等于把所有参数都减小：资产收益率下降与资金成本下降、价格下降与销量上升可能相反；风险因素的联动需要有经济解释。识别渠道去库存、订单取消、法规审批或关键客户流失等离散冲击，避免只测试小幅连续扰动。

保持正式低/中/高路径每年不交叉的既有契约。现实中的延期后追赶、周期转折或新旧产品替代可能产生交叉路径；用独立、有版本的压力分析记录这些路径，不能静默重排年度值，拼成没有连贯经营机制的情景。不同企业/行业不应共用无依据的固定概率。

Low/High 是条件情景边界。未定义概率分布和验证标称覆盖率时，不称为 80% 或 95% 预测区间。情景概率、参数不确定性、流程置信评分是不同概念。[Hyndman 与 Athanasopoulos：预测分布与区间](https://otexts.com/fpp3/prediction-intervals.html)

## 6. 区分会计分解、分配和因果推断

现有增长树用分析师权重分配分部净增量。这是解释性分配，不是通过数据识别的因果贡献，也不是关闭某驱动后重新计算出的增量。权重和为一只能证明分配闭合。分部净增量为零时，该算法无法展示相互抵消的正负机制；净增量为负时，权重的符号不等于收入影响方向。

优先用可重算桥解释量价变化。例如 R=Q×P 时，可以采用 Q 的贡献 ΔQ×(P0+P1)/2 与 P 的贡献 ΔP×(Q0+Q1)/2，两者精确加总为 ΔR；这是对交互项的对称分配，仍非因果识别。更多驱动可在研究中比较顺序桥或 Shapley 分配，但必须披露基准、交互分配方式和受约束重算逻辑。现有引擎未提供通用 Shapley/因果估计接口，不能声称已运行。

单参数敏感性回答局部模型影响；把所有敏感性相加会重复计算交互。主题反事实须明确“无主题”世界中需求、价格、容量的联动变化，不可只把主题收入标签改名。

## 7. 衡量准确性，先守住信息时点

使用预测冻结时确实可获得的数据构建滚动预测起点；每个起点重新估计可调参数。比较同一公司、口径、货币、信息截止日和预测期限；不能拿短期重估结果评价早期长期预测，也不能把事后重述历史混入原始可见信息。时间顺序的交叉验证用于检验预测未来的能力。[Hyndman 与 Athanasopoulos：时间序列交叉验证](https://otexts.com/fpp3/tscv.html)

研究复核同时看绝对误差、方向偏差、规模加权误差、不同期限和不同阶段的误差；零收入或小基数企业不依赖百分比误差。与固定收入、季节性朴素值或过去可用趋势等简易基准比较，基准复杂度必须匹配可用历史。样本内拟合不能证明预测准确。[Hyndman 与 Athanasopoulos：样本外准确性评估](https://otexts.com/fpp3/accuracy.html)

每次复盘把误差拆为需求/数量、净价/组合、时点、并表/汇率、会计口径与模型遗漏。用当时可见信息区分“执行错误”“假设错误”“合理但未实现的风险”，保留原预测，不用新叙事重写历史。小样本、同一公司重叠预测和共同宏观冲击会降低独立样本数；不要把它们当独立成功次数。

## 8. 研究审查与机器门槛的边界

| 项目 | 当前责任 |
|---|---|
| 来源日期/哈希、参数身份、公式、存量连续性、情景顺序、发布重算 | 运行时执行相应既有验证；以实际代码和模型契约为准 |
| 原始来源是否真实、搜索是否充分、同源材料识别、经济因果 | 研究者复核，主机凭据只能加强来源行为保证 |
| 外部基准选择、生命周期判断、失败样本、管理目标可信度 | 研究标准；已有字段登记支持证据与缺口，不新增伪代码门槛 |
| 参数校准、复杂模型优于朴素基准、概率区间校准 | 必须有匹配信息集的实证记录；没有记录就明确尚未验证 |
| 置信评分 | 证据和流程指标，不能解释为达成概率、准确率或投资胜率 |

交付前优先解决可能改变结论的大额缺口。剩余缺口进入正式 data_gaps/limitations；若缺口属于运行时硬门槛则保持阻断，若只是研究标准未满足则按实际状态披露，不能虚称代码验证通过即完成经济审查。盈利、现金流、治理评级、估值与仓位判断仍由对应 invest-* 模块处理。


## 9. 经营内容清单、角色与范围的可执行补充

先按实读原文列出 material target、新业务爬坡、确认条款、共享瓶颈、融资与竞争内容；每项记录 modeled/included/subscope/unmodeled/materiality_skip/unknown 与原因。包含于已有平台或分部的产品不能再加成独立收入。没有公开基期、TTM 与年度不匹配、租赁/最低保证与硬件销售不同，保留缺口而非造值。

历史收入表头只能支持基线/口径；需求走弱应进入反证，不能当正增长机制。经营机制说明方向，原文所示数量区间结合明确 period/scope 和转化假设才支持量级。主要 driver 至少尝试独立经营/外部 reference range；不可得时保留 unverified/conditional/stress，降低模型自由度、缩短明确预测期并解释剩余收入暴露。现有总分只衡量证据流程，新 optional adequacy 分列 documentary presence/mechanism/magnitude，不调整旧权重，不解释为准确率或达成概率。

可执行字段、两语言反例、原生公式校准、Q4→Q1 延期/取消与共享 cap、通用真实组装 CLI 见 [evidence-role-calibration.md](evidence-role-calibration.md)。季度/YoY 管理目标的原生分母、区间及 honest scope 见 [target-measurement-comparison.md](target-measurement-comparison.md)。这些 typed links 核对声明的引用与算术；独立研究者仍需核对原文、范围选择和经济反证。没有 frozen historical forecast 不伪称 backtest，资料不足不把 illustrative Low 宣称已校准。

## 10. 最大增量必须能拆到可比组件

当集团净增量主要来自一个聚合分部时，一个覆盖整个分部的“活动量指数”会把节奏完全不同的子业务压成一条路径。它在形式上合法（一个参数、一个公式），在解释力上是空的：它没有说明最大增量到底由谁贡献，也无法被任何同口径披露检验。

可执行的检查顺序：

1. **先确认互斥分区**。每个收入流只计一次；父分部包含子业务时，子业务不能被重复加总，也不能把“父减子”的差额当成独立披露的收入线。
2. **只用已识别的数量做桥**。可用的通常是：父分部精确数、一个子业务的四舍五入披露数、以及由披露增长率反推的可比基期。不可用的是：未披露的子业务 H2 拆分、产能体积、项目/客户/分子计数。
3. **把“条件推论”写成条件**。保持既有情景路径不变，问“在残余业务重复可比期的条件下，最大子业务隐含需要多少增长”，并给出倍数与百分比。这个隐含要求是分解恒等式，不是对最大子业务的预测，也不是新的 Base。
4. **把敏感性写成算术**。残余假设 ±10% 会改变隐含要求的方向和幅度——写清楚是“残余越高，同一总额要求的 D&M 越低”，并声明这是条件算术，不是经验区间。
5. **分母不许混用**。集团**净**增量、正向 driver 增量、分部增量是三个不同分母。同一份额在不同分母下数字不同，必须分别标注，不能互相替换来制造更高的集中度。
6. **反证要能改变东西**。每个反证写清楚它改变的是参数、情景、还是被证明的预测期；只修饰叙述的反证不算反证。

一个常见失败模式是“用管理层指引反推 Base”：先看到上调后的全年指引，再调活动量指数让 Base 落进区间。这会让预测失去独立性，也让后面的反证无法被检验。正确的做法是保持独立路径，把指引作为随后核对的基准，并如实报告偏离。

## 11. 未来不可观测量的诚实处理

公开资料经常缺少：子业务期间拆分、实现净价与组合、利用率与良率、合格交付、合同队列兑现节奏、取消率。这些量不能被“估一个合理值”填平，也不能因为缺失就把整个预测改成 null。

处理规则：

- 条件预测可以有非空数值；null 不是“谨慎”的同义词，编造才是错误。
- 每个未知量登记：它限制了哪条结论、影响多少金额（本币百万）、什么披露能解决它。
- 没有同口径观测区间时，`observed_range` 保持 null，校准状态保持 `unverified`；不得为了得到 `referenced_range` 而造端点。
- 不要把展示位舍入说成经验置信区间；不要用“反复微调参数直到审查通过”替代证据。
- 计算成功、校验通过、哈希一致都只是执行完整性，不是经济质量认证。

买方研究的交付物应当把“内部研究改进”和“经验校准未验证”分开陈述，并明确剩余外限限制了哪一项结论。
