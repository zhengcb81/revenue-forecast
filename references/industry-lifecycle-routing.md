# 行业、公司类型与生命周期路由

先确定收入合同与经营恒等式，再选择行业视角和生命周期覆盖。本表是研究路由，不是新的 schema 枚举；阶段、证据和风险须映射到已有 research_coverage、参数、增长树与缺口。模型存在不等于行业全部会计细节已被实现。

## 路由顺序

1. 确认会计主体、并表范围、分部外部收入、总额/净额及确认政策。
2. 区分客户、交易、产能、交付、合同服务、资源或资产收费等经济单位。
3. 按产品/业务而非整个公司判定阶段；同一公司可以同时有成熟现金业务、商业化新产品和衰退旧产品。
4. 选择最少充分模型；只有可证实的业务差异才拆分。分部合计须与报告收入闭合。
5. 应用下面的阶段修正与行业检查，再核对模型的已实现限制。

## 生命周期覆盖

| 阶段 | 主导问题 | 建模要求 | 重点反证/指标 |
|---|---|---|---|
| 预收入/研发/在建 | 是否、何时具备销售与确认条件？ | 明示零收入期、许可/试验/认证/投产节点；分清成功条件路径与概率加权期望；不从零基数计算 CAGR | 审批失败、试验终止、认证延迟、资金或工程进度导致的时间变化 |
| 初次商业化 | 试用是否转化持续付费？ | 资格客户→转化→可交付→净价；首单、试用、赠品与复购分开；按上市时间折算 | 客户验证、真实付费、退款、折扣、复购、渠道备货 |
| 扩张/快速增长 | 新客、新店、新地域能否复制？ | 新旧客户/门店/资产群分开，产能和销售能力约束；避免成熟收入水平即时赋给新增资产 | 新客质量下降、销售周期拉长、同店蚕食、扩张延期 |
| 成熟/饱和 | 存量续约、替换、价格和组合贡献多少？ | 分解保有、替换周期、净流失与净价格；市场上限须可服务而非总体 TAM | 渗透率见顶、替代品、客户用量收缩、折扣与返利 |
| 周期顶/底与复苏 | 库存和价格处于哪一段，转折是否可验证？ | 用多期周期基准，分开数量、净价、利用率与渠道库存；不把顶点利润/收入增速直线外推 | 库销比、订单取消、交期、供给投放、期现价差 |
| 衰退/收缩/退出 | 下降来自结构替代还是可逆周期？ | 明确客户流失、专利到期、停产、关店、处置及尾部服务；保持非负和边界条件 | 加速替代、渠道退出、合同终止、残余需求低于预期 |
| 转型/重组 | 新收入是否只是旧收入迁移？ | 新旧业务独立路径和迁移桥；按受控范围处理并表变化；新业务增长扣除蚕食 | 旧业务提前下滑、新业务毛留存低、重复计算系统销售 |

预收入企业的收入模型不评价资金是否充足，但现金约束若影响上市/投产日期，应把已验证时点假设放入收入路径，并将现金消耗分析交给 invest-financials。零基数、重大重组或会计变更下，绝对收入和逐年里程碑通常比 CAGR 更有意义。

## 行业与业务机制矩阵

下表模型 ID 均来自可执行模型库；新增高级结构或行业专属转换只有在 [model-library.md](model-library.md) 明列实现时才能调用。现有模型无法表达的阶段/桥接，应拆分业务、提供有证据的 derived 参数或使用透明的 direct_revenue 回退，不能杜撰驱动名。

| 行业/公司类型 | 可用基础路由 | 阶段修正 | 必查收入边界 |
|---|---|---|---|
| SaaS、信息服务、通信订阅 | subscription / cohort_subscription / subscription_arr_bridge | 扩张期新客时点；成熟期留存、席位/用量收缩；转型期许可迁移 | ARR、账单、RPO 与确认收入；NRR 包含扩张后不再重复加算 |
| 云计算、AI 推理/API、数据中心 | usage_platform / capacity_utilization / subscription | 初期可用容量与客户爬坡；成熟期利用率、价格下降与服务组合 | GPU 数量不是计费时长；分开托管、租赁、转售与服务净额 |
| 半导体、电子、汽车、装备 | unit_sales / capacity_utilization / delivery_pipeline / inventory_sellthrough / installed_base_aftermarket | 验证、良率、车型/节点上市；周期库存；成熟替换需求 | 出货与终端销售、寄售、退货、售后与软件分摊 |
| 航空航运、物流、酒店旅游 | transport / services / real_estate_rental | 可供座公里/吨公里/房晚与利用率，运力投放和季节性 | 运量单位与收益率分母匹配；附加费、退款与代理佣金 |
| 零售、餐饮、加盟、消费品 | retail_franchise / store_cohorts / unit_sales / inventory_sellthrough | 新店爬坡、同店、闭店、迁移与渠道库存 | 系统销售额不等于加盟收入；自营/加盟/供应链避免重复 |
| 电商、支付、交易所、出行平台 | usage_platform | 用户×频次×客单或交易额；成熟期净费率和补贴变化 | GMV/TPV 与净收入；本金、利息、商家补贴、principal/agent |
| 广告媒体、社交平台 | advertising | 活跃、时长、广告负载、填充、广告主需求 | 广告展示口径、无效流量、流量获取成本是否净额呈列 |
| 游戏、内容、教育 | gaming / subscription / services | 新品/学期群组、留存、递延确认与旧产品衰退 | MAU 与付费者重复；虚拟物品、课时和充值不等于收入 |
| 工程、军工、航天、软件实施 | project_backlog / delivery_pipeline / services | 研发认证→订单→履约；固定工期、取消与变更 | backlog 必须是未确认合同余额；按进度或验收确认不重复 |
| 矿业、油气、林业与农业 | resource / reserve_depletion / capacity_utilization | 建设爬坡、品位下降、枯竭、产量/价格周期 | 吨矿石/金属、回收率、payability、库存、权益产量与并表收入 |
| 发电、公用事业、管网、基础设施 | infrastructure / capacity_utilization / renewable_generation | 投运时间、负荷/资源禀赋、退役、费率重设 | 电量、容量服务与附加费分开；regulated 允许收入不等于售电额 |
| 地产开发、物业、REIT | delivery_pipeline / project_backlog / real_estate_rental | 开发、预售、交付、租约到期与空置恢复 | 土储/合同销售不是确认收入；物业管理、租金与资产出售分开 |
| 药品、疫苗、医疗器械 | commercial_launch / licensing_commercial / unit_sales / milestone_royalty / installed_base_aftermarket | 研发/审批/医保/渗透；专利到期后的量价侵蚀 | 患者×疗程与净实现价；折扣退货；里程碑是否满足确认条件 |
| 医院、诊断、医药研发服务 | services / unit_sales / project_backlog | 床位/设备/人员爬坡、就诊量、病例或订单组合 | gross billings 与净收入、医保结算、试验阶段与履约义务 |
| 银行、消费金融、券商 | bank_revenue / usage_platform / asset_management | 资产重定价、存款期限与资金成本；交易活动周期 | 净利息口径、日均资产负债、非息收入、负值分项的合法范围 |
| 资管、财富管理 | asset_management / aum_fee_bridge | 存量 AUM、净流入、市场回报和收费档位 | 收费 AUM 与总 AUM；业绩费门槛/结晶时点，不用固定 AUM 百分比代替 |
| 保险/再保险 | insurance_service / direct_revenue | 新单与存续服务群组、续期/退保及合同边界 | IFRS 17 保险服务收入不等于保费；财险/寿险/再保险不可套统一系数 |
| 分销、贸易、大宗中间商 | unit_sales / usage_platform | 周转、交易量和价格、去库存；总额转净额 | 主体/代理判断、促销返利、受托交易；大宗价格抬高收入不等于份额提升 |
| 多业务集团、控股、收购整合 | 按业务组合以上模型，加明确 company adjustments | 收购/出售生效时间、新旧口径可比桥 | 合并范围、权益法、不同比例持股不等于随意按持股比例缩放营业收入 |

`finite_adoption` 横跨多个行业，仅适用于可核验的首次采用/一次成交池；客户复购和售后收入应独立建模。新扩展模型的确切驱动、首年余额锚点和不支持事项见 [extended-models.md](extended-models.md)，不能从行业名称推定参数。

IFRS 17 把保险收入与保险财务损益分别呈列，并排除收入中的投资组成部分；其计量不是简单的“保费×确认率”。本路由只说明安全建模边界。[IFRS Foundation：IFRS 17](https://www.ifrs.org/issued-standards/list-of-standards/ifrs-17-insurance-contracts/)

## 公司特殊情况的横向覆盖

| 公司情形 | 处理方法 |
|---|---|
| 客户高度集中、单项目、单产品 | 按重要客户/合同/产品拆分；续约、取消和延迟用离散情景；不假定独立风险可以相互抵消 |
| 小公司、披露不足、历史短 | 优先透明简单模型和宽情景，显式列缺口；不能为提高显式模型评分制造无依据参数 |
| 跨国公司、通胀或汇率剧变 | 当地币种量价与汇率桥分开；同一效应不得同时进净价和公司调整；按适用报告政策核对 |
| 并购驱动、剥离、分拆、反向收购 | 保存 reported 和 comparable 历史，标注合并生效期间；有机增长从可复核桥计算 |
| 政府预算、监管定价、合同上限 | 从预算落实、招标、费率决定和履约时间传导；政策口号不构成订单 |
| 两边市场、免费转付费、新商业模式 | 区分用户侧与付费侧；网络效应必须落到转化/频次/留存，迁移不同时计作新客与旧客扩张 |

## 覆盖状态如何对外表达

“可路由到既有公式”“需要显式转换/拆分”“需 direct_revenue 回退”是研究表达，不是可靠性排名。只有运行了具体模型、输入通过对应契约并发布验证结果，才可称该次预测已执行。上述矩阵不宣称自动处理完整银行资产负债表、精算 IFRS 17、药物联合成功概率、统计生命周期识别或季度内排程；这些仍需领域研究、额外验证或其他模块。
