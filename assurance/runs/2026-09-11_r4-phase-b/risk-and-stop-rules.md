## 3. 硬停止清单（本 run 与后续 B 实施一体适用）

1. **越界写**：写到批准文件清单之外、或写到 `company-wiki/.source_catalog/**`、`raw/**`、`artifacts/**` → 立即停止并核对实际状态。
2. **未经批准的外发**：任何网络请求（含 LLM、provider、下载）→ 停（B 阶段设计上不需要网络）。
3. **未知费用/未知结果**：若出现"发出了但不知道结果"的动作 → 先对账，不重试。
4. **bad source/hash**：`content_sha256` 不符 → 显式失败，不回落另一份。
5. **真实 source 被 mock 替换**：B 的 R1 层必须用真实字节；mock 只允许出现在 D0 层并**明确标注**。
6. **必需测试 skip / rc0 但无输出**：不计通过（矩阵与 handbook §5）。
7. **基线漂移**：三仓 HEAD/配置/schema 与冻结值不一致 → 重做受影响部分的基线，不覆盖他人改动。
8. **超时无法取消 / 句柄无法关闭**：B03 的句柄生命周期若不能保证关闭 → 停止该实现方向，回到受控快照方案。
9. **归档/恢复集合不一致**：不在 B 范围；一旦发现涉及删除/恢复的动作被触发 → 停。
10. **隔离不足**：任何"必须在生产 catalog 上验证"的诱惑 → 停（G8）。

## 6. 提交前的"声明 vs 事实"自证（v0.1.5 新增，B-DR4-07 教训）

本轮四连拒的核心不是技术错误，而是**"我在 findings 里写了已修，文件里其实没改"**。故固化以下提交前检查：

1. **每写一条"已修"声明，立刻用 grep 自证**：例如写"R-6 表头改 11 处"，就跑 `Select-String -Pattern "11 处|9 处"` 确认新值在场、旧值不在场；
2. **跨文件一致性清单**：同一事实（版本号、计数、边界结论）在 `task_plan`/`b-design`/`file-scope`/`test-acceptance-map`/`checkpoint` 五处的取值必须一次对齐——**先 grep 全部出现点，再决定改哪几处**；
3. **生成器与断言必须真跑**：`--verify-only` rc=0；写路径在 index 与工作树不一致时**必须拒绝写出**（v0.1.5 已实现 rc=4）；
4. **未做的事不写"已做"**：不能落地的项写"登记/待批/不属于本包"，不写"已更正"；
5. **A 侧继承文本也要查**：`owner-rulings` 等阶段 A 文档若与 B 依赖的事实相反（R-2 的"两处"），必须在 A 侧就地更正，而不是在 B 侧绕开。
