## 4. 本卡自行犯下并已修正的判据错误（**两次**，如实登记）

### 错误 1 —— 「空范围」被当成了「负面结论」（**本项目第 20 次同源**）

**我写了什么**：为核对 ④ 的前提「`pytest-timeout` 是**新增**依赖」，我检查了 `requirements.txt` / `requirements-dev.txt` / `pyproject.toml` / `setup.cfg` / `pytest.ini` / `tox.ini`。

**我得到什么**：`declared_dependency_files_checked = []`，`pytest_timeout_already_declared = False` ⇒ 首版判据读出**「依赖不存在，前提成立」**。

**为什么是坏的判据**：**本仓库根本没有上述任何一个清单文件** ⇒ 判据**遍历了零个文件**。`False` 在这里的真实含义是**「我没看」**，而它的**呈现形态**是**「我看了，没有」**。两者**在输出上完全同形**。

⇒ **一般式**：**「空范围」必须与「负面结论」分开表示。** 一个搜遍零处的判据，其「未找到」**不是证据**。**判据必须能区分「搜过而未见」与「未曾搜过」** —— 本例的修正即为此加了一条**硬门** `scope_guard_not_vacuous`：**若实际未被搜索，该命题直接 FAIL，而不是真空通过**。

**修正**：改到**事实真正所在之处** —— 本项目的依赖声明是 CI 安装行
`.github/workflows/quality.yml`：`python -m pip install pytest cryptography "ruff==0.15.18" pytest-cov pyyaml requests "mypy==1.19.0"`。
**`pytest-timeout` 不在其中** ⇒ 前提**确实成立**。**但这个「成立」是这一次才取得的**，第一次的那个 `False` 是**运气好**（错的判据、碰巧对的方向）。

### 错误 2 —— 把**否定性断言**折进了 `all()` 的 AND（**命题因此不可满足**）

**我写了什么**：`p4["holds"] = all(v for k, v in p4.items() if isinstance(v, bool))`。

**为什么是错的**：`pytest_timeout_already_declared` 是**一条否定性断言** —— 我们**要的就是它 `False`**（依赖**不该**存在）。把它折进「所有 bool 都为真」，等于**同时要求**「该依赖不存在」与「该依赖存在被记为满足」⇒ **该命题结构上不可能为真**。

**症状**：所有**单个事实**都已是 `True` 且正确，而 `holds` 仍为 `False`。

⇒ **一般式（与错误 1 同族）**：**「我们想要的取值」与「为真的取值」不是一回事。** 一条命题里若混有**否定性断言**（「X 不存在」「未发生」「不得」），它就**不能**用「所有布尔项皆真」来汇总。**必须显式写出要求的极性**，否则命题要么**恒假**、要么在**将来某个无辜的变化**下**恒真**。

**修正**：改为**逐项显式列出**（`scope_guard_not_vacuous` ∧ `not pytest_timeout_already_declared` ∧ …），并写入 `holds_basis` 说明为何否定项**不得**折进 AND。

### （附）错误 3 —— 又一次被「硬换行」绊倒（第 17 次同源的原样复现）

首版判据要求 reviewer 的句子以**单空格**连接（`fires only *after* \`redact_text\` returns, so a full hang…`），而 `review.md` 在句中**硬换行** ⇒ 匹配失败。

**这与我上一卡刚刚写进 skill 的陷阱 17 是同一件事** —— 当时我的自检是「先归一化空白」，但我只归一化了 `[ \t]+`、**忘了 `\n`**。⇒ **「写进 skill」不等于「下次会用」**；**教训必须写进「默认动作」里**（本例已改为 `re.sub(r"\s+", " ", text)`）。
