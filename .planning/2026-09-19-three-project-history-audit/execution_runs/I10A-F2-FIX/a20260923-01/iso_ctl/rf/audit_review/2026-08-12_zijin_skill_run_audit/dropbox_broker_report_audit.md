## 可检索性实测判断

- 人工打开原 PDF 后，矿名、国家、资源/储量、产量和部分未来项目节点可以找到；代表性表格页视觉质量良好。
- 常规 catalog 用户却无法稳定查询这些事实，因为没有 MD/section/span、没有页码/表号、没有 actual/estimate 与单位标签，也没有 source-hash 绑定的派生物。
- 关键词搜索存在严重误归风险：比较型报告中的“陕西煤业 2028E ROE”可能被当成紫金预测；同一矿还存在 Timok/丘卡卢-佩吉/佩吉等别名。
- 个别嵌入字体会让纯文本抽取把“权益”等词解码异常；盲目 `pdftotext→Markdown` 不足以形成可信证据。

## 当场处理与 worker 提升

- 原 PDF 技术上可以当场处理；company-wiki 也存在 normalization/worker 管线。
- 但当前没有经过验收的、从 revenue-forecast 提交“按 source SHA + 需求字段”的受控优先处理合同。本次若直接修改 worker priority，会混淆调查与修复，并可能与正在运行的全库 worker 竞争。
- 因此本次只做只读抽查，没有生成共享 MD、没有入队、没有提优先级。系统应新增有回执的需求队列，而不是让各技能直接操纵 worker。

## 系统性改进方向

1. 把 `broker_research` 作为一等文档角色：从文件名和首页抽取发布日期、券商、公司和证券代码，支持一份比较报告绑定多个实体。
2. 生成绑定 source SHA、parser/schema/model/prompt 版本的 normalized MD、sections、page/table spans，并保留失败/partial 状态。
3. 增加表格保真层：页码、表号、行列标题、单位、实际/预测、资源/储量、100%/权益/并表口径必须一起保存和校验。
4. 建立通用矿山事实标签：`commodity / mine_asset / country / region / metric / period / actual_or_estimate / ownership_basis / consolidation_basis / unit / source_date`。
5. 让 consumer 以 source SHA 和字段需求提交幂等优先处理请求；跨 companies/dayu/Dropbox 只处理一次并复用 artifact。
6. 端到端测试必须验证：比较型报告不误归、最新与最完整来源可并存、逐矿事实有页码/表号/hash/单位、2028目标不会无依据变成2030事实。
