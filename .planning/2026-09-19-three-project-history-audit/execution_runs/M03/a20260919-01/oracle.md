## 2. 合成正例（positive）

输入（=`card_M03.md` L12-34 原文）：

```json
{"model_id": "unit_sales", "base_revenue": 0,
 "drivers": {"units": [120], "unit_revenue": [2.5], "timing_factor": [1], "other_revenue": [5]},
 "years": [2027]}
```

手算：`120 × 2.5 = 300`；`300 × 1 = 300`；`300 + 5 = 305` → **期望输出 `[305]`**（卡片 L36 一致）。

- 长度 1 = `len(years)`；容差 `1e-9 × max(1, 305) = 3.05e-7`。
- 若 `units[0] = 0` 且 `other_revenue[0] = 5` → 输出必须为 `5`（不得被当成 "0 量⇒跳过"）。

## 5. 连续性 / 额外检查

- `unit_sales` 是**流量乘数**模型，无期初/期末存量桥 → 存量桥资格 **not_applicable_with_reason**。
- Continuity positive：`units=[100,110]`、`unit_revenue=[2,2]`、`timing_factor=[1,1]`、`other_revenue=[0,0]`，
  `years=[2027,2028]` → 手算 `[200, 220]`，先运行通过。
- Continuity 断裂 patch：`years=[2027,2029]` → 预期 `ModelRegistryError`。
- **默认值检查（冻结预期）**：只给必填 `units=[10]`、`unit_revenue=[3]`，`years=[2027]`
  → 预期输出 `[30]`（`timing_factor` 默认 1.0、`other_revenue` 默认 0.0）。
  该检查证明默认值在**显式可验证**时行为正确，**不**授权缺披露时填 1/0。
- **signed `other_revenue` 探索（非通过/失败判据）**：`other_revenue = [-10]` 与 `units=0` 组合，
  记录实际行为（signed 域允许负 `other_revenue`，但**净收入为负**应被拒）。作为观察交 reviewer。
- **双重时间折算业务负例（不属 runtime 拒绝）**：若 `units` 已含全年暴露而仍填 `timing_factor<1`，
  runtime 不会拒绝（`[0,1]` 内合法），但**业务上必须停止**。这是 D/E 阶段的口径检查项，记 `special_review`。
