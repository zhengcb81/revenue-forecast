## REM-11 — scope the `bundle=None` path

### Finding under test
`select_artifact_roles` line 171 returns
`sorted({r for role in roles for r in _dag_closure(role)})` — the **downstream closure**
of the requested roles. With `roles=("normalized",)` and no bundle that yields all 5 roles
(`normalized, markdown, summary, sections, consumer_analysis`), which contradicts the
"ONLY requested missing roles + non-reusable ancestors" claim and card step 2.

### Frozen decision (the contested point)
The `bundle=None` branch must apply the **same scoping rule as the bundle-present branch**:
with no bundle every role is non-reusable, therefore

```
producer_events = requested roles  ∪  all transitive ancestors of requested roles
```

computed over the single imported `ROLE_DEPENDENCIES` (RF imports CW's copy — no second graph).
NOT the downstream closure; NOT a global "all roles" constant; NOT a special case.

The two branches must therefore be fed by one shared helper, so they cannot drift apart again.

### Expected values (hand-derived from the frozen active DAG)

Active DAG (D-W05): `normalized→[]`, `summary→[normalized]`, `sections→[normalized]`,
`consumer_analysis→[summary]`; historical `markdown→[normalized]` compatibility-only.

| request (`roles=`) | expected `artifact_read` | expected `producer_events` |
|---|---|---|
| `("normalized",)` | `[]` | `["normalized"]` — **NOT** all 5 |
| `("summary",)` | `[]` | `["normalized", "summary"]` |
| `("sections",)` | `[]` | `["normalized", "sections"]` |
| `("consumer_analysis",)` | `[]` | `["consumer_analysis", "normalized", "summary"]` |
| `("markdown",)` | `[]` | `["markdown", "normalized"]` |
| all five (default) | `[]` | `["consumer_analysis", "markdown", "normalized", "sections", "summary"]` (5, sorted) |

`artifact_read` is `[]` in every row: with no bundle nothing can be proven reusable.

Subset checks that the old downstream-closure code gets **wrong**:
- `("normalized",)` → old: 5 roles; expected: 1 role.
- `("summary",)` → old: `summary, consumer_analysis` (2 — falls *short* of the ancestor
  `normalized`); expected: `normalized, summary` (2, different set).
- `("sections",)` → old: `sections` (1 — missing ancestor `normalized`); expected: 2.

### The FC-904 question — is there a real conflict?

Frozen FC-904 acceptance test `tests/test_fc904_artifact_selection.py::test_no_bundle_all_produced`
asserts, for `select_artifact_roles(_handle(bundle=None))` with the **default** role tuple:

```
read == [] and produced == sorted(("normalized","markdown","summary","sections","consumer_analysis"))
```

`test_prepare_source_unavailable_envelope_all_produced` pins the same thing through
`prepare_source` (`producer_events == sorted(ALL_ROLES)`), and `source_preparation.py:139`
calls the selector **without** a `roles=` argument, so the default tuple is the live
production path.

**Frozen verdict: NOT a genuine conflict — the two requirements coincide, and the resolution
is to keep the default role tuple unchanged.**

Reasoning, recorded in advance so it cannot be reverse-engineered from the result:
- The reviewer's counterexample is a *subset* request (`normalized`-only). Under the new
  rule a subset request produces only that subset's ancestor-closure.
- FC-904's counterexample is the *universe* request (all five roles). Under the new rule the
  universe request still produces all five, because every role is requested; `markdown` is
  in the universe tuple, so its ancestor `normalized` and itself are produced.
- Therefore `test_no_bundle_all_produced` keeps passing **without editing the frozen test**,
  while the subset hole closes. No frozen assertion is weakened and no wording needs changing.
- Residual semantic shift that IS real and must be recorded rather than hidden: the *reason*
  the five roles are produced changes from "global default = produce everything" to
  "the default request names all five roles". The literal assertion is unchanged; the
  justification is not. `test_no_bundle_all_produced` therefore becomes a
  default-tuple-scope test, and this is documented in `decision.md` and in the new tests.

Had the default tuple been narrowed (e.g. to production roles only), FC-904 would have gone
RED and that would have been a genuine conflict requiring an owner ruling. That path is
rejected in advance: narrowing a frozen contract's default is not in this card's allowlist.
