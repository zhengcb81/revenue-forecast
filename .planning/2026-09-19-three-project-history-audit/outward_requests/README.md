# 对外请求函（TIER-2）

> **本目录的性质**：这三封函是 **owner 依 `OWNER_DECISIONS.md` 第十三节授权「联系与启动」**、
> 由编排层起草的**对外请求（request for adjudication）**。
>
> **它们不是裁定。** 收到函的任一方在本目录文件上签字**不产生**任何效力；
> **所有裁定必须落在各卡自己的载体上**（`decision.md` / `review.md` / `handoff.json` 的
> `reviewer_status` 等），按其卡的 `review_and_handoff.md` 口径书写。
>
> **执行纪律第 7 条**：owner 的总授权解除的是「启动与实施许可」；
> 凡专业裁判属他方者（TIER-2），最终结论**必须由该方出具**。
> 任何把本节读成「owner 已裁」的落地，等同**伪造签名**。

## 共同约束（三封函都适用）

1. **不得代签**：编排层、实现者、owner 均不得代收件方作答。
2. **不得以「按最佳实践」代替决定**（`START_HERE.md` 明文禁止）。每项须给出：
   **选择 · 理由 · 反例 · 兼容影响 · 恢复规则 · 被拒绝的替代方案**。
3. **不得编造证据**：缺真实样本 / provider 不可达 ⇒ 该项维持 `blocked`，
   不造绿色样例、不假装接口存在、不虚构数值。
4. **数值未定前不得写成规范值**：尤其 `W`/`T`/`L`（T2-8 / T2-15），
   裁决前任何人不得把具体秒数/字节数写进任何规范文本。
5. **回执落点**：请把结论写回**各卡自己的载体**，并在本目录
   `RESPONSES.md`（尚未建立）登记一行「函号 / 项号 / 收件方 / 结论落点 / 时间」，
   由编排层按事实转录，**不改一字裁决内容**。
